## Input authentication and identity

`load_inputs(reference)` accepts only the previous fixed feature manifest and membership pins. It reuses `retained_card_timing_coverage.verified_member` to authenticate all seven source roles per card and the complete original roster. A bounded snapshot reader reads each hash-bound file once, including the original retained HTML; callers may not substitute a different graph. Nothing follows a result reference.

The adapter additionally re-parses the primary page with the existing native runner parser. The complete box, canonical name token and race-entry ID field must match the sidecar, and the native race ID must agree. Only then does the existing `extract_thedogs_profile_identity` read the same-row `data-dog-id`, checking any corroborating profile links. A dog-profile ID and a race-entry ID remain different namespaces.

`runner_id` in the target packet is the original race-entry ID, allowing exact alignment to forecast inputs. `identity_id=thedogs:dog:<id>` is a verified source dog-profile identity for combining histories across cards. Missing or contradictory profile evidence leaves the target runner present with null identity and a neutral speed feature; no name-only fallback join is performed. Duplicate active dog-profile IDs or a changed native field reject construction.

The accepted source CSV has no native historical event ID. Historical events therefore remain explicitly conservative date/context proxies. The feature module groups each verified dog by historical date, collapses identical copies and excludes inconsistent copies. A repeated page or card is not another historical performance. The fingerprint covers the retained outcome-free timing projection, including `TIME`, `WIN`, `BON` and `PIR`, so equal `1 SEC` values do not hide contradictions in those fields. Those other fields are hashed, not used as candidate features or exported numeric inputs.

Each observation binds the accepted CSV path/hash, block row index, original target entry ID/box, primary HTML path/hash and receipt path/hash. The original completed pre-jump publication is a conservative availability upper bound for both the observation and its identity bridge. A later identity proof cannot be applied to an earlier target cutoff. The feature module filters availability before conflict grouping, so a later conflicting copy does not retrospectively invalidate an earlier prediction.

The fixed source contract's authenticated jump timestamp carries the source racing calendar offset. The adapter converts the decision instant to that recorded offset before date-only comparisons, preserving the instant while avoiding an accidental previous UTC calendar date. Root's metadata audit confirmed all 82 source jump and decision offsets are `+10:00`, so this conversion changes no current empirical cutoff. It is not a guessed worldwide track-timezone map; another source without this calendar contract requires its own adapter.

## Context and coverage accounting

The fixed source contains raw track codes and integer distances but no explicit sectional endpoint, layout or clock fields. Exact raw labels remain distinct. The generic venue configuration is not a verified sectional alias dictionary: it demonstrably pools Q1, Q2 and the Q straight in some legacy contexts. It is deliberately not imported by this adapter.

No exact source alias proof is present in the fixed input manifest, so this version applies **zero alias mappings** and emits `NO_EXACT_SOURCE_ALIAS_PROOF_IN_FIXED_MANIFEST`. It does not call different raw labels proven different physical tracks. The audit separates verified distance differences, distinct track labels of unresolved equivalence, sectional presence categories, invalid dates, same-day/future observations, missing/conflicting profile identities and prior-date context matches. Some counters are overlapping diagnostic dimensions, not an additive partition.

The audit emits a raw track/distance inventory per card so root can inspect any actual alias candidate against retained evidence. An alias must be supported by an exact retained source venue identity or equivalent primary-source proof before a later adapter version combines it. No fuzzy normalization, name similarity or observed sectional value establishes an alias.

The observation bank contains eligible historical copies from all 82 cards. Root supplies that bank to each target packet; the feature module selects only copies already available at that target's cutoff. This permits earlier retained observations to supplement later cards for a verified dog without peeking into later captures. The adapter does not discover or open additional external history. Additional already authorized cohorts need a separately authenticated adapter and remain separately accounted.

## User assumptions and validation

The user-supplied working meaning is that `1 SEC` is the individual dog's first sectional. `TIME` is total time but is not a candidate feature. These are exploratory assumptions, not new provider certification. Exact-context stability and cross-context standardized transfer remain modelling assumptions recorded by the feature protocol.
