Instead, `reconstruct_asof_card_history` uses only the **331 already-admitted, hash-bound development cards** and their retained, corroborated capture timestamps. It borrows a runner's history only from cards captured strictly before the target card's capture, which itself satisfies the existing T−60 gate. It never borrows later corrections or target results.

The sole variant unions observed starts by existing canonical runner token and date, collapses identical normalized rows, excludes the entire current field if a date has conflicting/ambiguous rows, retains newest 20, and recomputes the original 16 feature definitions. Whole-field current rosters and the original short feature values are verified exactly first. Context definitions, missingness and model method stay fixed. No provider request or new dataset population is involved. Canonical names are the established linkage key; no independent native cross-card runner ID is available. No ambiguous same-day history or name collision within a current roster was observed. Cross-card homonym risk cannot be disproved with this source surface and is an explicit exploratory limitation.
