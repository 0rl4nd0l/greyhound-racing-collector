## Executable route

`python -B -m scripts.development_examples seal` takes an explicit hash-pinned
access manifest, canonical race ID and private output directory. It admits
identity, the complete reservation baseline, allocation, opportunity accounting
and history permissions **before** opening data-bearing inputs. A pinned bundle
manifest rejects private `comparison/` members before the existing indexed
prediction verifier reads their payloads. The verifier authenticates the
existing exact capture receipt, retained inputs, frozen prediction and source
identities. No production caller imports the new module and no service hook is
enabled.

The output contains exact archived production sources, scoped retained history,
the original production feature rows/model probabilities, normalized same-time
fixed WIN market probabilities, active roster evidence and native runner IDs.
It separately records card-history v2 definitions, observed denominators and
missingness. Production DB/card rows and the unchanged production merge key
carry explicit accepted/duplicate decisions. A v2 card-quality field does not
replace the production feature or claim complete careers. The feature module
is reused unchanged from #198/#199; no research model code is imported.

Observation time is the collector's conservative fetch-start time; it is not a
provider-issued quote time. The retained-input completion is a conservative
durable availability bound. Append-start and file mtime are not availability.
The packet retains prediction, independent verification, index observation,
assembly and scheduled-jump timestamps. Actual off and absent native market IDs
remain null. The existing complete-field paired WIN/PLACE receipt proves the
WIN classification; one WIN snapshot is sufficient.

Source files and directory entries are fsynced before the packet is sealed.
Completion must publish before scheduled jump. Failure after partial output
preserves the attempt and cannot restart as success. An identical completed
call returns the existing seal without changing it.

`join` separately requires an exact per-race result authority linked to that
pre-result seal. It verifies the exported source package before the first
result-bearing read. The input result export contains the existing retained
official `race_rows` and `runner_rows`; its hash is a **normalized official
evidence hash**, not an asserted raw provider response hash. The existing
`OfficialResultSource` validator verifies source, race URL, date/number/venue,
full field, native runner IDs when supplied, capture time, unique complete
finish and winner. Derived labels must agree with those rows. There is no
mixed-result file reader, target database join or provider call in this module.
The operational result nomination exclusion remains unchanged: any future
collector/result export must receive the separate allocation/result authority.

Missing, ambiguous and void outcomes become durable nontrainable examples with
reasons. Dead heats require an ambiguous disposition in this initial route;
they are not silently converted to a single winner. Result collection/retry
allowances remain the operational owner's responsibility.

`verify` rechecks the standalone indexed bundle and recomputes both production
features (actual retained isolated interpreter worker) and source-history
provenance. Original collector paths are not needed for feature replay. The
complete access/reservation authorities remain required to authorize replay.
