# Persistent collector UI integration

Consume the authorized persistent collector read-only through a hash-pinned
collector configuration and source checkout. Follow current-day.json and the
immutable daily preparation chain on every refresh. Keep the existing retained
historical forecasts and manual prediction admission checks unchanged.

Today shows discovered upcoming races ordered by scheduled jump, inventory time,
collector status time and truthful stale/error states. Discovery alone never
means runner inputs or forecasts are ready. The Forecasts page displays all four
frozen candidates only after native verify_comparison validates their sealed
bundles and common pre-jump inputs. Label them engineering evidence, with the
scientific canary unchanged. No result access, provider calls, model changes or
collector writes. Verification runs in a bounded read-only, network-denied child.

UI deployment is coordinated with the collector owner, only during the authorized
idle window with no source acquisition, children or collector lock. No collector
restart or configuration mutation. Browser acceptance uses the established
shared authenticated headed session, and never submits a prediction.
